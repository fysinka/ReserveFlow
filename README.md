# ReserveFlow
Универсална система за резервации с React + Vite. Учебен проект със симулирани данни, без сървър.

## Стартиране
Инсталирайте Node.js 22 и отворете папката в VS Code. В терминала:
```sh
npm install
npm run dev
```
Отворете адреса, показан от Vite. `npm test` стартира тестовете; `npm run build` създава продукционна версия; `npm run preview` я показва.

## Функции
Четири бизнес конфигурации: медицински кабинет, салон, ресторант и спортен център. Избор на дата, продължителност, капацитет и търсене на ресурс. Свободните слотове се визуализират в зелено. Резервациите се създават, редактират и отказват. Данните се запазват в localStorage. Отказаните записи остават в историята.

## Архитектура
- `src/config.js` — конфигурации, начални данни, локална дата.
- `src/engine.js` — чисти функции за индексиране, валидация и генериране на слотове.
- `src/main.jsx` — React интерфейс, състояние, запис, мемоизирани ресурси.
- `src/style.css` — адаптивен интерфейс.
- `test/engine.test.js` — автоматизирани тестове.

## Модел на данните
Business: id, name, unit, open, close, step, durations, resources. Resource: id, name, capacity. Booking: id, business, resource, date, start, end, people, customer, status. Часовете са цели минути от полунощ. Капацитетът означава максимален размер на една група; всеки ресурс е ексклузивен за една резервация. Работното време е еднакво за всеки ден в конкретния бизнес. Нов бизнес се добавя чрез конфигурация, без нов алгоритъм.

## Алгоритъм и оптимизация
Интервалите са полуотворени [start,end): съседни резервации са позволени. Map индексира активните записи по бизнес, ресурс и дата. Сортирането по начало при неприпокриващи се интервали гарантира монотонност и на края. Двоично търсене намира първия потенциален конфликт за O(log k), където k е броят активни записи за ресурса и деня. Следват проверки до първия конфликт (или край на интервала), като при редакция се пропуска само собственият запис. Индексът се построява за O(N log N) в най-лошия случай, памет O(N). Генерирането на S слота е O(S log(k+1)+S). useMemo кешира индекса, филтрите и слотовете; useCallback и React.memo ограничават ненужните рендери. Индексът се построява отново при запис; това не е инкрементален индекс. Тестът сравнява двоичното търсене с линейна проверка при 1000 интервала; няма измерен React benchmark.

## Демонстрация
1. Изберете ресторант и 6 души — остават подходящите маси.
2. Изберете свободен слот и въведете име.
3. Опитайте да създадете резервация за същия ресурс и интервал чрез бутона Нова резервация — получавате грешка.
4. Редактирайте часа, след това откажете записа и проверете наличността.
5. Презаредете страницата — промените остават.
